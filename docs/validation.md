Executed on Linux x86_64, Python 3.12.14, uv 0.12.19, PySide6 6.12.0, NumPy 2.5.3, sherpa-onnx/core 1.13.8. The host has approximately 33 GB RAM and five available CPU cores, with no NVIDIA GPU or Apple Silicon. This is not a target-hardware performance report.

- New tests verify local asset hashes, relative bundle paths, refusal of missing assets without HTTP requests, complete split-GGUF shard verification and checksum-protected preparation/cache reuse, ambiguous attribution withholding, BPE reconstruction/word offsets, nonduplicated overlapping chunk ownership, global identity mapping, indexed long-recording interval lookup, pipeline cache reuse/settings invalidation, original audio integrity, child-process cancellation/reaping, offline GUI defaults without key/consent prompts, refusal to label a CPU run as GPU-accelerated, context token/grammar reference checks, recursive local source subdivision without lost text, and rejection of truncated output.
- Managed local-server protocol fixtures exercise authenticated loopback startup, proxy bypass, completion, resource cleanup, and cancellation during a blocked request. They use a controlled non-ML server, not learned GGUF inference. POSIX executable-script fixtures are skipped on Windows; portable protocol/unit tests still run there.
- Both official native engines compile successfully in the explicit CPU profile, with pinned revisions in scripts/build_engines.py. Their version/help entrypoints run. CUDA/Metal compilation and GPU inference are not validated by those CPU builds.
- Real sherpa-onnx ONNX inference processes the official 56.8607-second `0-four-speakers-zh.wav` release fixture using pyannote segmentation and WeSpeaker English/VoxCeleb ResNet34 embeddings. With the known expected count **4**, it yields 14 speaker turns across four IDs. This checks actual model loading/inference; it does not establish the correctness of every identity boundary.
- Automatic clustering at the upstream default threshold **0.5** yields only **2** IDs on that known four-speaker sample. This is observed under-clustering. Thresholds 0.35 and 0.4 both produce four IDs/14 turns with automatic counting on the same fixture. The release default is revised to **0.4**; this single-fixture correction is not universal accuracy calibration. Expected speaker count and threshold calibration remain important. Every local assignment is labelled uncalibrated/reviewable; uncertain overlap is left unassigned. Do not treat a stable ID as verified real identity.
- Source and rebuilt Linux bundle smoke checks exercise GUI initialization, project round trips, correction, local excerpts, seven exports, and actual WAV decoding/seek. The rebuilt bundle's isolated diarization worker is also checked with real ONNX models to catch missing native runtime libraries. Smoke checks are not learned ASR/LLM tests.

## Operational limits

Recognition/summary models run sequentially. Global CPU diarization still needs recording-wide buffers/intermediates and can dominate host RAM on very long recordings. The hard 24-hour limit is not a measured capacity guarantee. Normalized audio and sensitive diagnostics remain in local unencrypted caches for recovery. Token timestamps describe recognized originals, not forced alignment of later edits. Overlapped chunk decodes can disagree; a midpoint ownership rule does not repair transcription errors.

Citation grammar/IDs provide traceability, not proof of semantic support or external factual truth. Local instruction models can misinterpret valid evidence. Inspect all passages, stale markers and ambiguous/unsupported labels. Full Transcript Only skips LLM loading. Local excerpt mode is explicitly non-AI; topic excerpts are literal matching. Cloud providers remain opt-in and can continue charged processing after local cancellation.

## Target acceptance checklist

Prepare and verify a native bundle, disconnect internet access, then run scripts/benchmark_edge.py as described in edge.md. Import real speech; compare all recognized content/voice assignments to audio/ground truth; preserve the original hash; correct/rename/merge/split speakers; save/reopen; exercise search, active playback, speeds, scrub, bookmarks, every format/scope; generate separate speaker/topic/chronological/whole summaries and inspect every source. Cancel/restart in each phase and verify completed work is reused. Repeat on both targets with multi-hour speech, accents, noise, overlap and returning voices, measuring RAM/VRAM and accuracy rather than assuming them from unit tests.
